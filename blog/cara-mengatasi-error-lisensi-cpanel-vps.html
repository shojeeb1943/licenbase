Cara Mengatasi Error Lisensi cPanel pada Server VPS

By LicenBase Team Published October 12, 2026 4 min read

Melihat pesan error "Cannot Verify License" atau "Your cPanel & WHM license has expired" saat membuka WebHost Manager (WHM) dapat memicu kepanikan bagi admin server. Ketika validasi lisensi gagal, fitur manajemen WHM akan terkunci, pembuatan akun hosting baru terhenti, dan aktivitas klien terganggu. Namun jangan khawatir, sebagian besar masalah lisensi cPanel bukan disebabkan oleh pembatalan lisensi, melainkan kesalahan koneksi port firewall, perbedaan IP publik keluar, atau jam server yang tidak akurat. Dalam panduan sistematis ini, kami membagikan langkah-langkah praktis untuk memperbaiki error lisensi cPanel di VPS Linux Anda dalam hitungan menit.

1. Perintah Utama: cpkeyclt

Langkah pertama yang wajib dilakukan adalah membuka terminal SSH sebagai pengguna root dan menjalankan utilitas pembaruan lisensi resmi cPanel:

/usr/local/cpanel/cpkeyclt
  • Jika Berhasil: Updating cPanel license...Done. Update succeeded. — Segera refresh halaman WHM di browser Anda untuk membuka kunci.
  • Jika Lisensi Expired: Cek status lisensi aktif Anda di dashboard lisensi cPanel.
  • Jika Mengalami Timeout: Periksa koneksi jaringan dan firewall server Anda.

2. Buka Port TCP 873 pada Firewall Server

cPanel membutuhkan koneksi keluar (outbound) melalui port TCP 873 untuk protokol rSync ke server otentikasi. Jika Anda menggunakan CSF (ConfigServer Security & Firewall):

# Buka file konfigurasi CSF:
nano /etc/csf/csf.conf

# Pastikan port 873 terdaftar di baris TCP_OUT dan UDP_OUT:
# TCP_OUT = "20,21,22,25,53,80,110,143,443,465,587,873,993,995"

# Simpan lalu restart CSF:
csf -r

Uji koneksi port dengan menjalankan telnet auth.cpanel.net 873 untuk memastikan port tidak lagi diblokir.

3. Periksa Alamat IP Publik Keluar

Lisensi cPanel terikat langsung dengan alamat IPv4 publik utama server. Pastikan IP keluar server cocok dengan IP yang didaftarkan:

curl -4 ifconfig.me

Jika IP berbeda dari yang terdaftar di LicenBase, Anda dapat memperbarui IP di portal klien kami dalam hitungan detik.

4. Sinkronkan Waktu Sistem Server (NTP) dan Hapus Lock File

Validasi token SSL cPanel akan gagal jika jam server berselisih lebih dari beberapa menit dengan jam global:

# Sinkronkan jam dengan NTP:
timedatectl set-ntp true
chronyc makestep

# Hapus sisa file lock jika ada proses lisensi sebelumnya yang macet:
rm -f /usr/local/cpanel/cpanel.lck

Setelah jam tersinkronisasi dan file lock dibersihkan, jalankan kembali perintah /usr/local/cpanel/cpkeyclt.

5. Memeriksa Log Kesalahan Lisensi cPanel

Jika lisensi masih menolak untuk aktif, periksa catatan log internal cPanel untuk melihat akar masalah yang sebenarnya:

tail -n 30 /usr/local/cpanel/logs/license_log

Log ini akan menampilkan apakah terjadi penolakan akibat IP mismatch, sertifikat SSL lokal kadaluarsa, atau kegagalan DNS resolver di /etc/resolv.conf.

6. Masalah DNS Resolver dan Konfigurasi resolv.conf

Ketika server cPanel tidak dapat menyelesaikan nama host server otentikasi (seperti auth.cpanel.net), perintah cpkeyclt akan mengalami kegagalan koneksi domain. Buka file konfigurasi DNS resolver Anda dengan perintah nano /etc/resolv.conf dan pastikan Anda menggunakan DNS publik yang cepat dan andal, seperti Google Public DNS (8.8.8.8 dan 8.8.4.4) atau Cloudflare DNS (1.1.1.1). Hindari penggunaan nameserver internal VPS lokal yang sering mengalami pemeliharaan tanpa pemberitahuan.

7. Memperbarui Sertifikat SSL Internal cPanel

Jika sertifikat SSL internal server kedaluwarsa, pertukaran kunci kriptografi dengan server lisensi dapat terputus. Anda dapat memperbarui sertifikat layanan internal cPanel secara manual dengan menjalankan perintah /usr/local/cpanel/bin/checkallsslcerts --force. Perintah ini akan memvalidasi ulang sertifikat untuk layanan WHM, cPanel, Webmail, dan FTP secara menyeluruh sehingga verifikasi lisensi berjalan lancar kembali.

Setelah sertifikat diperbarui, lakukan restart pada service cPanel daemon dengan perintah /usr/local/cpanel/scripts/restartsrv_cpsrvd. Langkah ini memastikan bahwa semua soket koneksi SSL yang sedang aktif di-refresh dengan sertifikat baru yang valid, sehingga komunikasi terenkripsi dengan server otentikasi dapat terjalin kembali tanpa hambatan atau pesan peringatan keamanan di browser web.
