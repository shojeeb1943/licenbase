Como Resolver Alto Uso de CPU e RAM em Servidor VPS Linux

By LicenBase Team Published October 12, 2026 5 min read

Manter um servidor VPS Linux funcionando de forma estável e ágil exige monitoramento constante dos recursos de hardware. Quando o uso de CPU chega a 100% ou a memória RAM física se esgota completamente, o sistema operacional começa a usar a memória swap do disco, os sites apresentam lentidão extrema e o banco de dados MariaDB pode ser subitamente finalizado pelo mecanismo OOM Killer (Out Of Memory). Antes de gastar dinheiro contratando planos de VPS mais caros na nuvem, é essencial diagnosticar a origem do gargalo e aplicar otimizações nos serviços. Neste guia prático, apresentamos os comandos, técnicas de análise e procedimentos essenciais para solucionar problemas de sobrecarga de CPU e RAM no Linux.

1. Comandos de Diagnóstico Rápido: top, htop e free

O primeiro passo ao notar lentidão é acessar o terminal SSH e inspecionar os recursos em tempo real com ferramentas nativas do sistema:

# Verificar o consumo de memória física e swap:
free -h

# Identificar os 10 processos que mais consomem memória RAM:
ps aux --sort=-%mem | head -n 11

# Monitoramento interativo:
htop

No htop, verifique a barra de Load Average e a coluna MEM% para descobrir se o gargalo é provocado por processos do PHP, do MariaDB/MySQL ou do servidor web Apache.

2. Otimizando os Pools de Processos do PHP-FPM

Se você hospeda múltiplos sites em WordPress, os processos do php-fpm costumam ser os maiores consumidores de memória. Se o parâmetro pm.max_children for configurado em um valor muito alto, dezenas de workers serão criados simultaneamente sob picos de tráfego, esgotando toda a RAM:

  • Calcule a Memória Disponível: Se cada processo PHP consome cerca de 60 MB e você possui 2 GB livres para o PHP, o valor máximo seguro de pm.max_children deve ser por volta de 30 a 35 workers.
  • Defina o Gerenciamento Dinâmico ou OnDemand: Configure pm = ondemand para servidores com poucos acessos para liberar memória RAM quando os sites estiverem ociosos.
  • Defina o limite de requisições: Defina pm.max_requests = 500 para reiniciar workers periodicamente e eliminar vazamentos de memória (memory leaks) de scripts PHP mal desenvolvidos.

3. Reduzindo o Consumo de Memória do MySQL / MariaDB

O MariaDB aloca grandes blocos de memória para buffers de tabelas. Ajustar o arquivo de configuração /etc/my.cnf pode evitar o esgotamento prematuro da memória RAM:

  • Ajuste do innodb_buffer_pool_size: Em servidores compartilhados, configure o buffer pool para cerca de 40% a 50% da memória RAM total, evitando que o banco concorra com o servidor web.
  • Controle de Conexões Concorrentes: Reduza o max_connections para 100 ou 150, impedindo que centenas de conexões ociosas consumam RAM desnecessária.
  • Log de Consultas Lentas (Slow Query Log): Ative o slow_query_log = 1 e long_query_time = 2 para registrar consultas que demoram mais de dois segundos e precisam de índices.

4. Controlar Tarefas Cron e Backups em Horários de Pico

Rotinas automatizadas de backup e cron jobs pesados de plugins como o WooCommerce ou backups do cPanel podem consumir 100% da CPU se forem executados durante o dia:

  • Agendamento Noturno: Transfira todos os backups automáticos para a madrugada (entre 02:00 e 05:00), quando o tráfego de visitantes é mínimo.
  • Prioridade de Processos com nice e ionice: Execute scripts de manutenção com prioridade baixa (nice -n 19 ionice -c 3 backup-script.sh) para que eles não travem as requisições web.

5. Acelerando o Servidor com LiteSpeed e CloudLinux

Para servidores com grande volume de acessos diários, substituir o Apache tradicional por uma licença LiteSpeed reduz o consumo de CPU em até 70% graças ao cache LSCache a nível de servidor.

Além disso, a implementação de uma licença CloudLinux impede que qualquer conta de cliente monopolize a CPU ou a memória física, isolando cada usuário em gaiolas virtuais seguras. Conheça também nossos combos promocionais para turbinar seu cPanel VPS com custos mínimos e estabilidade absoluta.
