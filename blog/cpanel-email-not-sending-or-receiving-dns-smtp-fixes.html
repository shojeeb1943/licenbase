cPanel Email Not Sending or Receiving? DNS, SMTP & Mail Fixes

By LicenBase Team Published October 12, 2026 5 min read

Reliable email communication is fundamental to modern business operations. When a client reports that transactional receipts are not delivering, customer inquiries are missing, or messages sent from cPanel webmail are bouncing back with cryptic SMTP errors, resolving the issue quickly is critical. In modern hosting environments, email failures rarely stem from broken software; rather, they are caused by missing DNS authentication records, ISP port blocks, or mail queue congestion. In this guide, we break down the end-to-end cPanel email delivery pipeline, covering SPF, DKIM, DMARC, Reverse DNS (PTR), and Exim terminal troubleshooting.

1. Configure Mandatory DNS Authentication: SPF, DKIM & DMARC

In 2024, Google and Yahoo introduced strict authentication standards for all bulk and transactional senders. Sending mail without cryptographic signatures and verified sender records guarantees high spam placement or outright delivery rejection:

  • SPF (Sender Policy Framework): A DNS TXT record specifying which server IP addresses are authorized to send mail on behalf of your domain. A standard cPanel SPF record looks like: 
    v=spf1 +a +mx +ip4:203.0.113.10 ~all
  • DKIM (DomainKeys Identified Mail): Uses a 2048-bit cryptographic key pair. The server signs outgoing message headers, and receiving servers verify the signature against your public DNS key located at default._domainkey.yourdomain.com.
  • DMARC (Domain-based Message Authentication): Establishes a policy telling mailbox providers how to handle emails that fail SPF or DKIM checks. A baseline DMARC record published at _dmarc.yourdomain.com: 
    v=DMARC1; p=quarantine; pct=100; rua=mailto:dmarc-reports@yourdomain.com

Inside cPanel, navigate to Email Deliverability to review your status. Click Manage next to any domain to let cPanel generate and install verified SPF and DKIM records automatically.

2. Set Up Reverse DNS (PTR Record) with Your VPS Host

Forward DNS points your domain name to an IP address (e.g., mail.yourdomain.com -> 203.0.113.10). Reverse DNS (rDNS) does the exact opposite: when a receiving mail server receives a connection from 203.0.113.10, it queries the IP to verify that it resolves back to mail.yourdomain.com.

If your VPS IP address lacks a matching PTR record, recipient servers will categorize your server as an unverified residential node or compromised botnet. Note that PTR records cannot be set inside cPanel; they must be configured in your VPS cloud provider's networking console (e.g., OVH, Hetzner, Vultr, DigitalOcean).

3. Verify Outbound Port 25 Connectivity

To combat automated spam generation from newly created cloud servers, most cloud infrastructure providers block outgoing traffic on TCP port 25 by default. When port 25 is blocked, your mail server can receive incoming emails (over port 25), but cannot connect to external destination mail exchangers.

Test outbound port 25 connectivity via SSH terminal:

# Test connection to Google SMTP servers over port 25
nc -zv -w 5 smtp.gmail.com 25

# Expected successful output:
# Connection to smtp.gmail.com 25 port [tcp/smtp] succeeded!

If the command hangs or times out, outbound port 25 is blocked by your datacenter. Open a support ticket with your VPS hosting provider to request port 25 unblocking, or configure an external SMTP relay like SendGrid, Mailgun, or Amazon SES in WHM under Exim Configuration Manager > Smart Host.

4. Inspect the Exim Mail Queue and Flush Stuck Messages

cPanel uses Exim as its default Mail Transfer Agent (MTA). When message delivery encounters temporary errors (such as remote rate limiting or greylisting), Exim queues the message for automated retry.

Use these terminal commands to inspect and manage the Exim queue:

# View current number of messages waiting in the queue
exim -bpc

# List messages currently in the queue with status details
exim -bp

# Force immediate delivery attempt for all queued messages
exim -qff

# Remove all frozen messages from the queue
exipick -z -i | xargs exim -Mrm

# Monitor real-time mail server log transactions
tail -f /var/log/exim_mainlog

Frequently asked questions

Major email providers (Google, Yahoo, Microsoft) enforce strict authentication requirements. If your domain lacks valid SPF, DKIM, and DMARC records, or if your server IP lacks a matching Reverse DNS (PTR) record, receiving servers will flag messages as suspicious or drop them completely.

Many cloud providers (DigitalOcean, AWS EC2, Linode) block outbound SMTP port 25 by default to prevent spam botnets. You can test connectivity from your server terminal using `telnet smtp.gmail.com 25` or `nc -zv smtp.gmail.com 25`. If the connection times out, request an unblock from your host.

To flush the entire Exim mail queue and force immediate delivery attempts for frozen or deferred messages, run `exim -qff` via root SSH terminal.

All inbound and outbound mail transactions, bounce messages, and authentication failures are recorded in `/var/log/exim_mainlog`. You can inspect live mail flow using `tail -f /var/log/exim_mainlog`.
