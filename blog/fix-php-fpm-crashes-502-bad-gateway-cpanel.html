How to Fix PHP-FPM Crashes and 502 Bad Gateway in cPanel

By LicenBase Team Published November 11, 2026 5 min read

Encountering an unexpected '502 Bad Gateway' error across hosted websites is one of the most frustrating experiences for server administrators running cPanel & WHM. In a modern cPanel architecture, Apache delegates dynamic PHP request processing to PHP-FPM via Unix domain sockets. When worker pools exhaust their connection limits, crash due to memory leaks, or hang on slow queries, Apache drops the connection and returns HTTP 502. This technical guide explains how to diagnose, recover, and permanently tune PHP-FPM pools to eliminate crashes.

1. How cPanel Implements PHP-FPM and Unix Domain Sockets

In cPanel & WHM, PHP-FPM operates as an independent systemd service (e.g., ea-php81-php-fpm, ea-php82-php-fpm). Apache communicates with each domain's pool through dedicated Unix domain sockets located in /opt/cpanel/ea-phpXX/root/usr/var/run/php-fpm/.

When a visitor requests a page, Apache proxies the connection through the domain's .sock file. If the socket is missing, unreadable, or all worker children are saturated, Apache times out and returns 502 Bad Gateway or 503 Service Unavailable.

2. Step 1: Diagnose PHP-FPM Crash Logs via CLI

To pinpoint the exact failure reason, inspect the master PHP-FPM error log for your active PHP version:

tail -n 50 /opt/cpanel/ea-php82/root/usr/var/log/php-fpm/error.log

Look for warning signatures such as:

  • WARNING: [pool domain.com] server reached pm.max_children setting (5), consider raising it — Indicates worker starvation during traffic surges.
  • WARNING: [pool domain.com] child 12345 exited on signal 9 (SIGKILL) — Indicates the Linux kernel Out-Of-Memory (OOM) killer forcibly terminated a worker that exceeded memory limits.
  • ERROR: failed to post fastcgi_finish_request() — Points to socket disconnections or premature Apache client aborts.

3. Step 2: Emergency Service Recovery Commands

If PHP-FPM has crashed and left websites offline, execute an immediate graceful service restart via SSH as root:

/scripts/restartsrv_apache_php_fpm
/scripts/restartsrv_httpd

If an orphaned .sock file is preventing the daemon from binding, regenerate the pool configuration files cleanly:

/usr/local/cpanel/scripts/php_fpm_config --rebuild
/scripts/restartsrv_apache_php_fpm

Ensure your underlying cPanel license is active and verified, as licensing state changes can restrict automated configuration scripts.

4. Step 3: Enable the PHP-FPM Slow Log for Diagnostics

To identify the specific PHP scripts causing worker threads to hang until the pool is exhausted, configure the PHP-FPM slow log. In your pool configuration, enable:

request_slowlog_timeout = 5s
slowlog = /var/log/php-fpm/slow.log

Whenever a script takes longer than 5 seconds to respond, PHP-FPM automatically dumps the call stack and file line numbers into slow.log, showing you which WordPress plugin or unindexed SQL query is starving the pool.

5. Step 4: Optimal Pool Tuning in WHM MultiPHP Manager

To stop 502 errors permanently, tune your domain's PHP-FPM pool parameters inside WHM:

  1. Navigate to WHM > MultiPHP Manager > User Domain Settings.
  2. Click Edit PHP-FPM next to the affected domain.
  3. Adjust the process manager configuration:
    • pm: Switch from static to ondemand (for low-traffic sites to save RAM) or dynamic (for high-traffic WooCommerce sites).
    • pm.max_children: Increase from default 5 to 20 or 40 depending on available RAM. Formula: (Available RAM in MB) / 60MB.
    • pm.max_requests: Set to 500. This recycles worker processes after handling 500 requests, completely eliminating gradual PHP memory leaks.
    • pm.process_idle_timeout: Set to 10s to release dormant workers quickly.

6. The High-Concurrency Alternative: LiteSpeed Web Server

While PHP-FPM can be tuned, its process-bound architecture requires substantial memory allocations under sudden traffic spikes. Deploying an accelerated LiteSpeed license replaces Apache and PHP-FPM with the high-performance LiteSpeed Server API (LSAPI).

LSAPI operates up to 5x faster than PHP-FPM with significantly lower memory usage and zero 502 socket drops. For hosting environments managing multiple client websites, pairing LiteSpeed with a managed VPS provides the ultimate high-availability web stack.

Frequently asked questions

A 502 Bad Gateway error indicates that Apache (the front-end reverse proxy) attempted to forward a dynamic request to the PHP-FPM service, but the PHP-FPM daemon was either stopped, crashed, unresponsive, or running out of worker threads.

The most common cause is reaching the 'pm.max_children' threshold. When all worker children are busy processing long requests, new incoming connections queue up and eventually time out, causing Apache to return a 502 error.

Run '/scripts/restartsrv_apache_php_fpm' to restart all active PHP-FPM version daemons simultaneously, or restart Apache using '/scripts/restartsrv_httpd'.

Determine the total RAM allocated to PHP-FPM (e.g., 70% of available server RAM) and divide it by the average memory consumed by one PHP process (typically 40MB to 70MB for WordPress). For 4GB dedicated RAM, (4096 / 60) gives ~68 max_children.

Enabling 'request_slowlog_timeout = 5s' records full PHP stack traces for any request executing longer than 5 seconds into a dedicated slow.log file. This pinpoints exact slow database queries, hung external API calls, or looping plugins.
