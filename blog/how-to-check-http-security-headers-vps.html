How to Check HTTP Security Headers: A Practical VPS Guide

By LicenBase Team Published October 15, 2026 4 min read

When hardening a web server, administrators frequently focus on firewalls, SSH keys, and SSL certificates while completely overlooking one of the most critical front-line defenses: HTTP security response headers. HTTP security headers are standardized instructions sent by your web server (such as Apache, Nginx, or LiteSpeed) informing the visitor's web browser how to safely handle website content, restrict dangerous frame embeds, enforce HTTPS encryption, and neutralize Cross-Site Scripting (XSS) attacks. Without these headers, even websites with valid SSL certificates remain vulnerable to clickjacking, credential theft, and MIME-type sniffing exploits. In this practical guide, we explain how to check your HTTP security headers and implement them across your VPS.

The 5 Essential HTTP Security Headers

To achieve an "A+" rating on modern web security audits, your server should transmit the following core headers with every HTTPS response:

Security Header Recommended Value Primary Defense
Strict-Transport-Security (HSTS) max-age=31536000; includeSubDomains Forces HTTPS; prevents SSL Stripping
X-Frame-Options (XFO) SAMEORIGIN Blocks Clickjacking / iframe embedding
X-Content-Type-Options nosniff Prevents executable MIME sniffing
Referrer-Policy strict-origin-when-cross-origin Protects sensitive URL query strings
Content-Security-Policy (CSP) default-src 'self' ... Blocks unauthorized script injection (XSS)

How to Check Headers: CLI vs Free Online Tools

You can audit your website's active response headers using several quick methods:

  • Terminal cURL Method: Execute this one-line command from any terminal to inspect headers: 
    curl -s -D - -o /dev/null https://yourdomain.com
    Look for the presence of strict-transport-security, x-frame-options, and content-security-policy in the output.
  • Free Browser Tools: Use our free online Security Headers Checker and HTTP Headers Viewer to analyze all response headers, identify missing security directives, and generate ready-to-copy server configuration code.

These tools test whether your server passes strict PCI-DSS and OWASP recommendations, flagging insecure configurations before attackers can exploit them. Regularly auditing headers ensures that newly installed plugins, content delivery networks (CDNs), or reverse proxies do not inadvertently strip critical security flags.

How to Configure Security Headers in Apache, LiteSpeed, and Nginx

Implementing security headers on your server is straightforward and requires only a few directives:

  1. Apache & LiteSpeed (.htaccess): Add the following snippet to your website root .htaccess file: 
    <IfModule mod_headers.c>
Header always set Strict-Transport-Security "max-age=31536000; includeSubDomains; preload"
Header always set X-Frame-Options "SAMEORIGIN"
Header always set X-Content-Type-Options "nosniff"
Header always set Referrer-Policy "strict-origin-when-cross-origin"
Header always set Permissions-Policy "geolocation=(), microphone=(), camera=()"
</IfModule>
  2. Nginx (nginx.conf / vhost): Add directives inside your server block: 
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Permissions-Policy "geolocation=(), microphone=(), camera=()" always;

On servers powered by a high-speed LiteSpeed license, these headers are cached at the web server level, adding zero latency to dynamic responses.

When applying Strict-Transport-Security with the preload flag, ensure that all subdomains on your apex domain possess valid SSL certificates, as browsers will strictly refuse non-HTTPS connections once enrolled in the global HSTS preload list.

Frequently asked questions

The five most essential headers are HTTP Strict Transport Security (HSTS), Content-Security-Policy (CSP), X-Frame-Options, X-Content-Type-Options, and Referrer-Policy.

Run curl -I https://yourdomain.com in terminal to view raw response headers. You can also use free online tools like our LicenBase Security Headers Checker.

X-Frame-Options is a legacy header supported by older browsers to stop clickjacking. CSP frame-ancestors is the modern replacement that allows fine-grained domain whitelisting. Modern servers implement both for maximum backwards compatibility.

An overly strict Content-Security-Policy (CSP) that blocks inline scripts or external CDNs can break themes or analytics tags. Always test CSP policies using Content-Security-Policy-Report-Only before enforcing them live.

HSTS Preloading registers your domain into Google Chrome, Firefox, and Safari core binary code, guaranteeing that browsers never connect over plaintext HTTP even on the first visit. Requirements include max-age of at least 31536000 seconds, includeSubDomains, and the preload flag.
