How to Find Largest Files on a Linux VPS: Free Disk Space

By LicenBase Team Published October 19, 2026 5 min read

Running out of disk storage on a production Linux virtual private server is an emergency. When a filesystem reaches 100% capacity, MySQL/MariaDB daemons crash to prevent table corruption, email servers bounce incoming customer messages with "Disk Quota Exceeded", and cPanel fails to write temporary session files. Before you purchase an expensive disk upgrade from your VPS host, you can often reclaim tens of gigabytes of disk space in under five minutes by finding and purging bloated log files, stale backup archives, and orphaned package caches. In this tutorial, we share the fastest Linux commands to identify and safely clean the largest files on your server.

1. Checking Overall Filesystem & Inode Capacity

Start by identifying which partition has exhausted its storage:

df -h

Next, check filesystem inodes (the total number of files permitted on disk):

df -i

If df -h shows plenty of free gigabytes but df -i reports 100% inode utilization, thousands of tiny cache files (such as PHP session files in /var/cpanel/php/sessions or WordPress transients) are paralyzing your filesystem.

2. Top Commands to Locate Files Larger than 100MB

To pinpoint the largest individual files across your entire server, execute:

find / -type f -size +100M -exec ls -lh {} + 2>/dev/null | awk '{ print $5, $9 }' | sort -hr | head -15

Sample diagnostic output:

18G /var/log/httpd/error_log
8.2G /var/lib/mysql/ibdata1
4.1G /home/user/backup-10.19.2026.tar.gz
2.3G /var/log/journal/849204820482048/system.journal

This single command immediately exposes runaway log files, uncompressed database tables, and forgotten backup tarballs consuming gigabytes of NVMe storage.

3. Finding the Heaviest Directories with du

If individual files appear small but directories are bloated with millions of items, sort folder sizes:

du -ahx / 2>/dev/null | sort -rh | head -20

The -x flag ensures du stays on the current filesystem, skipping virtual mountpoints like /proc, /sys, and /dev.

For an interactive visual interface, install and launch ncdu:

dnf install ncdu -y || apt install ncdu -y
ncdu /

You can browse directories using arrow keys and press d to delete offending files instantly.

4. Reclaiming Space from Open Deleted Files (lsof)

A classic Linux sysadmin trap occurs when an administrator runs rm huge_file.log, but df -h still reports 100% disk usage. This happens because the web server daemon still holds an open file handle to the deleted file:

lsof +L1

Sample output showing deleted files still occupying disk sectors:

COMMAND   PID USER   FD   TYPE DEVICE SIZE/OFF NLINK NAME
httpd   14201 root    2w   REG  253,0  1849201928     0 /var/log/httpd/error_log (deleted)

To release the disk space immediately without rebooting your VPS, restart the offending daemon:

/scripts/restartsrv_httpd

5. Quick-Win Cleanups for Common Bloat Locations

Run these safe cleanup routines to reclaim immediate headroom:

  • Vacuum Systemd Journals: journalctl --vacuum-size=200M
  • Clean Package Caches: dnf clean all || apt clean
  • Delete Archived Gzip Logs: find /var/log -type f -name "*.gz" -delete
  • Purge Abandoned cpmove Tarballs: find /home -maxdepth 2 -name "cpmove-*.tar.gz" -delete
