How to Fix AutoSSL Errors in cPanel: DNS & DCV Troubleshooting

By LicenBase Team Published October 14, 2026 5 min read

The introduction of automated TLS certificate provisioning via cPanel AutoSSL revolutionized website security. By automatically issuing and renewing free 90-day certificates from Let's Encrypt or Sectigo across all domains, subdomains, and mail services, AutoSSL eliminated expired certificate warnings for millions of websites. However, when AutoSSL encounters a validation error, websites display terrifying browser warning screens ("Your connection is not private - NET::ERR_CERT_DATE_INVALID"), destroying user trust and tanking search engine rankings. In almost all instances, AutoSSL failures are caused by Domain Control Validation (DCV) breakdowns, DNS mismatches, or restrictive redirection rules. Here is how to diagnose and resolve cPanel AutoSSL errors decisively.

Understanding the AutoSSL DCV Verification Process

Before a Certificate Authority (CA) issues an SSL certificate, it must cryptographically verify that your cPanel server owns the domain name. AutoSSL performs this verification using the HTTP-01 challenge:

  1. AutoSSL writes a temporary cryptographic token into public_html/.well-known/acme-challenge/<TOKEN>.
  2. The CA sends an outbound HTTP request over port 80 to http://yourdomain.com/.well-known/acme-challenge/<TOKEN>.
  3. If the server returns the exact token string with HTTP 200 OK, domain ownership is verified and the signed certificate is installed automatically.

If any intermediate firewall, redirection rule, or DNS mismatch blocks this HTTP request, DCV fails.

1. Check the AutoSSL User Log in WHM or CLI

Never guess the failure reason. Inspect the detailed AutoSSL execution log directly:

# View the most recent AutoSSL log for a specific cPanel user
tail -n 60 /var/cpanel/logs/autossl/*_user_username.log

# Or trigger an immediate check via CLI
/usr/local/cpanel/bin/autossl_check --user=username

The log will state precisely which domain failed and the exact HTTP response code received during the ACME challenge.

2. Fix .htaccess HTTPS Redirection Conflicts

The most common cause of DCV failure is aggressive .htaccess rewrite rules that force all incoming HTTP requests to HTTPS before the certificate even exists, or that intercept requests to .well-known:

# Add this exception at the top of your public_html/.htaccess file:
RewriteEngine On
RewriteCond %{REQUEST_URI} !^/\.well-known/acme-challenge/
RewriteCond %{HTTPS} off
RewriteRule ^(.*)$ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]

This exception ensures that Let's Encrypt validation requests over plain HTTP port 80 reach the token file directly without triggering redirect loops.

3. Verify DNS A Records Across All Subdomains

AutoSSL attempts to secure every subdomain configured in WHM, including mail.domain.com, cpanel.domain.com, and webmail.domain.com. If any of those subdomains point to an old server IP or lack an A record, AutoSSL will fail the entire batch:

# Query DNS resolution for root and subdomains
dig A yourdomain.com +short
dig A mail.yourdomain.com +short
dig A www.yourdomain.com +short

If you use external DNS (like Cloudflare), ensure that every subdomain has an active A record pointing to your server's IPv4 address. Temporarily disable the Cloudflare proxy (orange cloud to grey cloud) during initial SSL issuance if caching blocks token verification.

4. Resolve CAA Record Restrictions in DNS

Certification Authority Authorization (CAA) records tell DNS resolvers which Certificate Authorities are allowed to issue certificates. If a domain has a CAA record that only permits DigiCert or Sectigo, Let's Encrypt cannot issue a certificate:

# Check for existing CAA records
dig CAA yourdomain.com +short

# If using Let's Encrypt, ensure this record is present in DNS:
yourdomain.com. IN CAA 0 issue "letsencrypt.org"

5. Clear Stale DCV Cache Files

Occasionally, cPanel caches failed DCV attempts, preventing immediate retries even after DNS has propagated. Clear the cache files safely:

rm -rf /var/cpanel/ssl/dcv/*
/usr/local/cpanel/bin/autossl_check --user=username
