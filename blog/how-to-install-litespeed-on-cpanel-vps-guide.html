How to Install LiteSpeed on a cPanel VPS: Step-by-Step Guide

By LicenBase Team Published October 4, 2026 4 min read

Upgrading your cPanel & WHM server from default Apache to LiteSpeed Web Server is one of the most impactful performance optimizations you can perform. With LiteSpeed, your server gains native HTTP/3 QUIC capability, edge-level caching for WordPress, and dramatically reduced CPU load. Best of all, the entire installation and migration process can be completed in under 15 minutes with zero downtime for your hosted websites.

Prerequisites and License Preparation

Before starting the installation, ensure your VPS meets the following conditions:

  • Root SSH access to your cPanel & WHM server.
  • An active cPanel & WHM license running EasyApache 4.
  • An active, whitelisted LiteSpeed license registered with LicenBase.

Step 1: Install the LiteSpeed WHM Plugin

Connect to your VPS terminal as root and execute the official LiteSpeed cPanel plugin installation script:

# Download and execute the LiteSpeed WHM installer
cd /usr/src
curl -sL https://www.litespeedtech.com/packages/cpanel/lsws_whm_plugin_install.sh | bash

Once complete, log into WHM and navigate to Plugins > LiteSpeed Web Server Plugin.

Step 2: Install LiteSpeed Web Server Binaries

In the LiteSpeed WHM plugin dashboard:

  1. Click Install LiteSpeed Web Server.
  2. Accept the license agreement.
  3. Set your administrative credentials and email notification address.
  4. Set Port Offset to 2088. This allows LiteSpeed to run on port 2088 alongside Apache on port 80/443 so you can test website functionality safely before switching production traffic.
  5. Click Build Matching PHP to automatically synchronize all active PHP extensions, IonCube loaders, and modules from your EasyApache 4 profile.

Step 3: Switch Traffic to LiteSpeed (Zero Downtime)

Once testing on port 2088 confirms your websites render properly, switch live traffic:

  1. In the LiteSpeed WHM plugin, click Switch to LiteSpeed.
  2. Confirm the prompt. LiteSpeed stops Apache and binds directly to ports 80 and 443 instantly.
  3. Click LiteSpeed Cache Management to enable automated LSCache for WordPress across all cPanel accounts.

Your cPanel VPS is now fully powered by LiteSpeed Enterprise. For ongoing peace of mind and license continuity, manage your licenses through LicenBase bundles.

Step 4: Post-Installation Fine-Tuning and Optimization

After successfully switching your cPanel server traffic to LiteSpeed, apply these essential optimizations in the LiteSpeed WebAdmin console (https://your-server-ip:7080):

  • Enable Gzip and Brotli Compression: Navigate to Server > Tuning and verify that Brotli compression is enabled for text/html, application/javascript, and text/css MIME types.
  • Configure PHP Process Limits: Under Server > External App > LSAPI PHP, set Max Connections to match your server RAM capacity (e.g. 50-100 for a 4GB VPS, 200+ for an 8GB VPS) to prevent memory exhaustion during traffic spikes.
  • Enable CloudLinux LVE Integration: If your server runs CloudLinux, LiteSpeed automatically connects to LVE Manager to enforce per-user CPU, RAM, and I/O limits in real time.

Troubleshooting Common Post-Install Issues

If you notice any unexpected behavior after switching to LiteSpeed, review these standard diagnostic checks:

# Check if LiteSpeed is actively listening on ports 80/443
netstat -tulpn | grep lshttpd

# Check LiteSpeed runtime status
/usr/local/lsws/bin/lswsctrl status

# If port conflict occurs with stale Apache processes
killall -9 httpd
/usr/local/lsws/bin/lswsctrl restart

Summary: Verification Commands After Installation

Once your installation and traffic switch are complete, verify all subsystems with these quick terminal commands:

# Check LiteSpeed HTTP/HTTPS listeners
netstat -lnp | grep -E "(:80|:443)"

# Check PHP LSAPI build and active modules
/usr/local/lsws/fcgi-bin/lsphp82 -m

# Verify LSCache response header via curl
curl -I https://yourdomain.com | grep -i "x-litespeed-cache"

If the response header displays X-LiteSpeed-Cache: hit, your server is delivering edge-cached pages directly from memory in under 40 milliseconds.
