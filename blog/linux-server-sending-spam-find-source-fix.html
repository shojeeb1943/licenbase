Linux Server Sending Spam Emails? Find the Source & Stop Abuse

By LicenBase Team Published October 20, 2026 7 min read

Few operational emergencies disrupt hosting operations as rapidly as an outbound spam explosion. When a compromised mailbox or malicious PHP script begins pumping millions of unsolicited messages through your Exim mail transfer agent, your server IP gets blacklisted across global RBLs within hours. Legitimate client emails fail to reach Outlook, Gmail, or Yahoo, and hosting providers face immediate network suspension notices. This hands-on guide provides the diagnostic commands and remediation steps to locate the exact spam leak, purge malicious mail queues, and harden Exim against persistent email abuse.

1. Warning Signs: RBL Blacklists, Delivery Delays, and High Queue Sizes

Outbound email abuse often goes unnoticed until customers complain that their normal business emails are bouncing. Key symptoms of an ongoing spam campaign include:

  • Exploding Exim Queue Size: The mail queue jumps from dozens of messages to tens of thousands of deferred or frozen records.
  • Non-Delivery Reports (NDRs) Flood: Postmaster and system mail accounts are overwhelmed with "Mail Delivery Failed: Returning message to sender" notifications.
  • RBL & DNSBL Blacklisting: Your server IP is flagged on Spamhaus ZEN, Barracuda, or SpamCop, causing recipient mailservers to reject connections with 550 5.7.1 Service unavailable.
  • Port 25 Bandwidth Spikes: High persistent outbound network bandwidth generated by the mail transfer agent (MTA) process.

2. Inspecting the Exim Mail Queue via SSH

To diagnose the problem, log into your server terminal via SSH as root. The first step is to generate an aggregate summary of the messages currently waiting in your Exim queue:

# View current queue total count
exim -bpc

# View queue breakdown grouped by domain and age
exim -bpr | exiqsumm

Sample exiqsumm output highlighting an ongoing spam flood:

Count  Volume  Oldest  Newest  Domain
-----  ------  ------  ------  ------
 8420   42MB    3h      1m     gmail.com
 4110   21MB    3h      2m     yahoo.com
 2350   12MB    3h      1m     hotmail.com
-------------------------------------
14880   75MB    3h      1m     TOTAL

If you observe thousands of emails queued for major consumer domains within a narrow time window, an unauthorized sender is actively abusing your mail relay.

3. Differentiating Compromised Email Accounts from Malicious PHP Scripts

Outbound spam generally originates from one of two sources: a legitimate email user whose password was compromised via phishing or dictionary attack, or an unauthenticated PHP webshell injected into a CMS. You must inspect individual message headers to determine which attack vector is active.

List the oldest 10 messages currently in the queue to obtain their unique Exim message IDs:

exiqgrep -o 3600 -i | head -n 10

Pick one message ID (e.g., 1t3X8a-0004ab-12) and dump its full headers:

exim -Mvh 1t3X8a-0004ab-12

Carefully analyze the header output for the following forensic indicators:

  • Compromised Authenticated Mailbox: If the headers show auth_id: sales@example.com or received_protocol: esmtpsa, an actual mailbox was hijacked. Attackers frequently use residential botnets to connect via Dovecot SMTP with stolen credentials.
  • Malicious Web Script: If the headers contain X-PHP-Originating-Script: 1002:mailer.php or show U=cpaneluser with a working directory pointing to /home/cpaneluser/public_html/wp-content/uploads/, a rogue PHP script is executing via the web server daemon.

If headers point to a script, inspect the message body to confirm the content:

exim -Mvb 1t3X8a-0004ab-12

Reviewing the message body confirms whether it contains banking phishing lures, lottery scams, or pharmaceutical advertisements.

4. Purging Frozen Spam Messages and Freezing Abusive Senders

Once you identify the abusive origin, stop the leak immediately to protect your server's IP reputation before beginning deep file cleanup.

If a specific mailbox was compromised, suspend outbound access immediately via WHM or reset the email account's password. Next, purge all queued spam sent from that specific address:

# Remove all queued messages from a specific sender email
exiqgrep -i -f compromised_user@example.com | xargs exim -Mrm

# Remove all frozen bounce messages to free disk space and reduce queue load
exiqgrep -z -i | xargs exim -Mrm

If thousands of messages remain queued from an unauthenticated PHP user, remove messages sent by that system user:

exiqgrep -i -f '<>' | xargs exim -Mrm
exiqgrep -i -c 'cpaneluser' | xargs exim -Mrm

Re-check exim -bpc to verify that the queue is clearing rapidly.

5. Remediating Hijacked Scripts and Enforcing WHM Outbound Limits

If the source was a malicious PHP script, locate and neutralize the file immediately. Use the script filename identified in the X-PHP-Originating-Script header:

# Search for rogue mailer scripts in the suspected account
find /home/cpaneluser/public_html -type f -name "mailer.php" -ls

# Quarantine the script by stripping execute and read permissions
chmod 000 /home/cpaneluser/public_html/wp-content/uploads/mailer.php

To ensure that a single compromised account can never flood millions of messages again, enforce hard outbound email limits in WHM:

  1. Log into WHM > Tweak Settings > Mail.
  2. Set "Max hourly emails per domain" to a reasonable threshold (e.g., 100 to 200 emails per hour).
  3. Set "The percentage of email messages (per domain) that may fail or defer within an hour" to 15%. If an account sends to invalid scraped lists with high bounces, cPanel automatically blocks outbound mail for that domain for the remainder of the hour.
  4. Enable "Query Apache server status for that user" so Exim logs the exact HTTP request URI that invoked the mailer script.

6. Restoring Domain Reputation and Hardening Email Authentication

After purging the queue and stopping the leak, you must clean up your server's sending reputation to ensure legitimate messages are delivered:

  • Delist from Blacklists: Visit MXToolbox or MultiRBL, check your server IP, and submit delisting requests on major RBLs (Spamhaus, Barracuda, Invaluement) after confirming the queue is completely clean.
  • Validate Reverse DNS (rDNS): Ensure your server's primary IP has a valid PTR record matching your hostname (e.g., server.yourdomain.com). Outbound mail servers reject IPs with generic PTRs.
  • Enforce SPF, DKIM, and DMARC: In WHM > Email Deliverability, verify that all hosted domains have valid SPF records (v=spf1 +ip4:YOUR_IP ~all) and aligned 2048-bit DKIM keys.
