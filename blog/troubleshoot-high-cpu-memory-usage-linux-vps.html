How to Troubleshoot High CPU and Memory Usage on Linux VPS

By LicenBase Team Published November 11, 2026 4 min read

Encountering sudden CPU spikes and RAM exhaustion on a Linux VPS is one of the most stressful operational events for website owners and systems administrators. When load averages exceed available processor cores, web applications slow down, database connections drop, and HTTP 504 Gateway Timeouts emerge. This comprehensive technical guide provides a systematic, CLI-driven diagnostic pipeline to isolate and eliminate the root causes of server bottlenecks.

1. Step 1: Diagnose System Load and IO Wait with vmstat

Before assuming that raw CPU computing power is the problem, check whether your server is actually bottlenecked by disk input/output wait (wa). Run vmstat with a 1-second refresh interval:

vmstat 1 5

Analyze the two key output columns under cpu:

  • us (User Time): High values (70%+) indicate computationally intensive tasks like unoptimized PHP loops, image processing, or crypto-mining scripts.
  • wa (IO Wait): High values (20%+) indicate that your CPU is sitting idle waiting for storage read/write operations to complete. This points to heavy disk swapping, unindexed database queries, or disk hardware saturation.

2. Step 2: Identify Process Hotspots with htop and ps

Launch htop to inspect active processes and memory consumption in real time:

htop

Press P to sort by processor usage or M to sort by physical resident memory (RES). On multi-tenant servers running a cPanel license, process ownership clearly exposes the offending tenant username:

ps aux --sort=-%cpu | head -n 10
ps aux --sort=-%mem | head -n 10

If you see dozens of spawned php-fpm: pool [username] processes consuming all available RAM, that specific user account is experiencing either a traffic surge or an automated brute-force attack.

3. Step 3: Inspect Database Slow Queries and Locks

In web hosting environments, runaway MySQL queries are responsible for over 60% of unexpected CPU spikes. Connect to MySQL as root and inspect active execution threads:

mysql -e "SHOW FULL PROCESSLIST;" | grep -v Sleep

Look for queries stuck with high execution times displaying states like Sending data, Copying to tmp table, or Locked. Terminate an abusive thread immediately with KILL [Process_ID]; and enable the MySQL slow query log in /etc/my.cnf to identify queries requiring table indexes.

4. Step 4: Track Disk IO Bottlenecks with iotop

If vmstat revealed high IO wait, run iotop to identify which specific daemon or process is saturating the storage controller:

iotop -oPa

The -oPa flags display only processes actively performing disk IO and accumulate total read/write bytes. If you notice MySQL or Exim thrashing disk writes, check your server swap usage with free -m. When physical RAM is exhausted, Linux swaps memory pages to disk, causing catastrophic IO wait spikes.

5. Long-Term Stabilization: CloudLinux LVE & Managed VPS

Troubleshooting server spikes manually is unsustainable for growing hosting businesses. The permanent architectural solution is deploying an automated CloudLinux license. CloudLinux Lightweight Virtual Environments (LVE) enforce strict per-user CPU and RAM caps, isolating abusive accounts so your server never crashes.

For organizations looking for enterprise infrastructure managed by 24/7 Linux sysadmins, upgrading to our managed VPS or elastic unmanaged VPS instances delivers high-performance NVMe storage with zero CPU steal time.

Frequently asked questions

High load average with low CPU percentage indicates severe disk IO wait (wa). When database or logging processes wait on slow disk read/writes, threads queue in the kernel run-state (D-state), spiking the load average without maxing out processor cores.

Run 'htop' and press F6 to sort by PERCENT_CPU or PERCENT_MEM. In cPanel servers, user processes run under the tenant's username, allowing you to instantly identify which account is responsible for the load spike.

Log into MySQL via root and run 'SHOW FULL PROCESSLIST;'. Inspect queries with long 'Time' values that show 'Copying to tmp table', 'Locked', or 'Sorting result', which indicates missing database indexes.

Deploy CloudLinux OS with Lightweight Virtual Environments (LVE). CloudLinux enforces strict per-user CPU, RAM, IO, and concurrent process limits, ensuring that one runaway script never degrades the rest of the server.
