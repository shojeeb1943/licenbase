VPS Server Too Slow? 15 Performance Fixes for CPU, RAM, Disk & Network

By LicenBase Team Published October 6, 2026 5 min read

Nothing frustrates website visitors and customers faster than a sluggish, unresponsive server. When a cloud VPS server experiences slow response times, high time-to-first-byte (TTFB), or frequent 504 Gateway Timeouts, identifying the exact root cause can feel overwhelming. Server bottlenecks typically stem from four distinct hardware vectors: CPU thrashing, RAM exhaustion, slow disk I/O, or network congestion. In this comprehensive troubleshooting guide, we present 15 actionable, production-tested fixes to restore blazing speed and rock-solid stability to your Linux VPS server.

Category 1: Resolving CPU Spikes and Runaway Tasks

When server load average exceeds the total number of vCPU cores, CPU queueing causes noticeable response lag:

  • 1. Pinpoint and Terminate Runaway PHP Processes: Use htop or run ps aux --sort=-%cpu | head -n 10 to find hung PHP processes stuck in infinite loops.
  • 2. Stagger Scheduled Cron Jobs: Hosting accounts often schedule daily backup and maintenance crons at midnight (0 0 * * *). Stagger crons across odd minute intervals (e.g. 17 3 * * *) to avoid simultaneous CPU spikes.
  • 3. Enable PHP OPcache: Ensure Zend OPcache is enabled in php.ini (opcache.enable=1, opcache.memory_consumption=128). This keeps pre-compiled bytecode in RAM, eliminating repeated script compilation overhead.
  • 4. Block Abusive Scrapers and Bots: Bot traffic scraping wp-login.php or xmlrpc.php burns enormous CPU cycles. Use a Web Application Firewall to block automated bad bots at the edge.

Category 2: Memory (RAM) Optimization & Swap Tuning

RAM exhaustion forces the Linux kernel to swap pages to disk, causing severe I/O degradation and Out-of-Memory (OOM) killer terminations:

  • 5. Lower Linux Swappiness to 10: The default swappiness of 60 swaps memory to disk far too early. Edit /etc/sysctl.conf and add vm.swappiness = 10, then run sysctl -p.
  • 6. Right-Size PHP-FPM Worker Pools: If pm.max_children is set too high, concurrent traffic spikes will exhaust all physical RAM. Calculate: (Total RAM - 1GB) / Average PHP Process Size (60MB).
  • 7. Deploy Redis Object Caching: Install Redis to cache persistent database query results in memory, eliminating redundant SQL executions for dynamic websites.
  • 8. Prune Unused Background Daemons: Disable unnecessary services (such as mailman, spamassassin if using external mail, or named if using Cloudflare DNS) to free up hundreds of megabytes of RAM.

Category 3: Disk I/O & MySQL Database Acceleration

Slow disk input/output operations cause thread locks and prolonged database wait states:

  • 9. Tune InnoDB Buffer Pool Size: In /etc/my.cnf, set innodb_buffer_pool_size to 50%–70% of available server RAM for dedicated database instances. This ensures entire database tables fit in RAM.
  • 10. Enable MySQL Slow Query Logging: Add slow_query_log=1 and long_query_time=2 to log queries taking longer than 2 seconds, then add missing database indexes.
  • 11. Convert Legacy MyISAM Tables to InnoDB: MyISAM locks the entire table during writes. Convert tables to InnoDB to enable row-level locking and crash recovery.
  • 12. Truncate and Rotate Bloated Log Files: Check /var/log for multi-gigabyte log files using du -sh /var/log/* and configure logrotate to keep disk capacity healthy.

Category 4: Web Server & Network Optimization

Modernizing your web server architecture delivers immediate 3x to 10x throughput gains:

  • 13. Switch from Apache to LiteSpeed Web Server: Deploying a LiteSpeed license replaces Apache's heavy thread model with asynchronous event-driven I/O, slashing CPU utilization by up to 70% and providing full LSCache support.
  • 14. Enable Google TCP BBR Congestion Control: BBR replaces old packet-loss algorithms with real-time bandwidth estimation, improving throughput over high-latency network connections:
# Enable TCP BBR in sysctl
echo 'net.core.default_qdisc=fq' >> /etc/sysctl.conf
echo 'net.ipv4.tcp_congestion_control=bbr' >> /etc/sysctl.conf
sysctl -p
  • 15. Enable Gzip and Brotli Compression: Ensure Brotli and Gzip compression are active in your web server configuration to compress HTML, CSS, and JS payloads by up to 75% before transmission.
